# เลือกรายการที่จะอยู่ใน sync script: การออกแบบ

วันที่ 2026-11-14 · สถานะ: สร้างเสร็จแล้ว (ดูหัวข้อ "ที่ต่างจากแผนตอนสร้างจริง" ท้ายไฟล์) · ยังไม่ได้ commit

## ทำไม

ฐานข้อมูลที่เทียบกันมีความต่างจากงานของหลายคน หลายโปรเจ็ค (stored procedure, table, column ฯลฯ)
ผู้ใช้รู้ว่าตัวไหนเป็นงานของตัวเอง แต่ตอนนี้ `.sync.sql` และ `.rollback.sql` รวมทุกความต่างไว้ในไฟล์เดียว
ผู้ใช้ต้องการติ๊กเฉพาะของตัวเองแล้วได้ script ที่มีแค่ตัวนั้น ส่วนที่เหลือให้เจ้าของไปเลือกเอง

## เป้าหมาย

1. ในรายงานของรันที่เปิดจากแอป ทุกแถวความต่างติ๊กได้ ติ๊กแล้วได้ sync script และ rollback script
   ที่มีเฉพาะแถวที่ติ๊ก ไม่ว่าจะเป็นหมวดไหนหรือสถานะไหน
2. ถ้าติ๊กทุกแถว ต้องได้ script เหมือนที่การเปรียบเทียบเขียนไว้ทุกตัวอักษร
   (ต่างได้เฉพาะค่าที่เปลี่ยนทุกครั้ง เช่น เวลา)
3. rollback ของชุดที่เลือกย้อนเฉพาะสิ่งที่ sync ของชุดเดียวกันทำ
4. ถ้าติ๊กตัวที่ต้องพึ่งตัวที่ไม่ได้ติ๊ก (เท่าที่ตรวจได้) ต้องบอกก่อนให้ดาวน์โหลด

## ไม่ใช่เป้าหมาย

- เลือกข้ามหลายฐานแล้วได้ไฟล์เดียว ปุ่ม "Sync script ทั้งหมด" ของ batch ยังรวมทุกตัวเหมือนเดิม
- จำหรือแชร์ชุดที่เลือก (รีโหลดหน้าแล้วหาย)
- รัน script ให้เอง
- ติ๊กได้ในไฟล์รายงานที่เปิดนอกแอป และในรายงานของหน้า drift
- เปลี่ยนวิธีหาความต่าง หรือเปลี่ยน script เต็มที่เคยสร้าง

## สิ่งที่ห้ามเกิด (แม้ทำงานได้ตามตัวอักษร)

- script ขาดสิ่งที่ผู้ใช้ติ๊ก หรือมีสิ่งที่ไม่ได้ติ๊ก
- ได้ script ที่รันแล้วพังกลางทางเพราะตัวที่พึ่งอยู่ ทั้งที่หน้ารู้และเตือนได้
- รายงานโหลดอะไรจากข้างนอก หรือตัวอักษรเล็กกว่า 14px (เทสต์ `report.test.ts` คุมอยู่)
- หน้าแสดงช่องติ๊กทั้งที่สร้าง script ไม่ได้

## ข้อจำกัดของโปรเจ็ค

- engine เป็น Windows PowerShell 5.1 (`Compare-Database.ps1`, `lib/SyncScript.ps1`) ส่วนแอปเป็น Node 22 ไม่มี dependency
- API ทุกเส้นต้องมี header `X-Database-Diff: 1` (กัน request ข้ามเว็บ)
- ไฟล์ทั้งโปรเจ็คเป็น CRLF ข้อความในรายงานเป็นภาษาไทย ฟอนต์ระบบเท่านั้น
- ผลของรันในแอปมีครบเสมอ: `<base>.json` (รายการความต่างพร้อม `SourceKey`/`TargetKey`) และ
  `<base>.source.snapshot.json`, `<base>.target.snapshot.json` เพราะแอปส่ง `-SaveSnapshots` ทุกครั้ง
  ยกเว้นฝั่งที่เป็น snapshot อยู่แล้ว (engine ไม่เก็บสำเนา): `-SourceSnapshot` ทำให้ `perspective` เป็น `timeline` (หน้า drift)
  ซึ่งหน้ารายงานไม่แสดงส่วนเลือก ส่วนรันที่มีแต่ `-TargetSnapshot` ยังเป็น `sync` แต่ขาดสำเนาฝั่ง target
  เซิร์ฟเวอร์ต้องตอบ 409 ที่อ่านรู้เรื่อง ไม่ใช่ error ดิบ
- แถวในรายงานกับ `diffs` ใน `.json` เรียงลำดับเดียวกัน: `toRows` ใน `templates/report.html` ตั้ง `id: i`
  และ `Write-HtmlReport` สร้าง `DATA` จาก `$Diffs` ตามลำดับ จึงใช้ตำแหน่ง (นับจาก 0) เป็นตัวระบุแถวได้
- ประวัติถูกลบอัตโนมัติ (เก็บ 90 วัน) รันที่ถูกลบแล้ว หรือรันที่ไม่มี snapshot ต้องตอบข้อผิดพลาดที่อ่านรู้เรื่อง

## ทางที่พิจารณา

- **ก. ติ๊กในหน้ารายงานเดิม (ผู้ใช้เลือก):** ใช้รายการที่ผู้ใช้อ่านอยู่แล้ว (จัดตามตาราง ค้นหา กรองชนิด ดูโค้ดต่าง)
  ข้อเสียคือไฟล์ `.html` ที่ส่งต่อไปเปิดเฉย ๆ ติ๊กไม่ได้
- **ข. หน้าใหม่ในแอปสำหรับเลือก:** รายงานคงเป็นไฟล์นิ่ง แต่ต้องสร้างรายการ ค้นหา กรอง ดูโค้ดต่าง ซ้ำอีกชุด
  และคอยให้สองหน้าตรงกัน
- **ค. ปุ่ม "เอา script ตัวนี้" ทีละแถว:** ไม่เลือก เพราะผู้ใช้เลือกหลายตัวพร้อมกัน
- **ง. ประกอบ script ในเบราว์เซอร์จาก SQL ที่ฝังไว้ในรายงาน:** ไม่เลือก ต้องเขียนลำดับคำสั่ง, transaction, rollback
  ใหม่อีกภาษา เสี่ยงผิดกว่ามาก (ใช้ได้กับไฟล์ที่ส่งต่อ แต่ผู้ใช้ไม่ได้ขอ)

## การออกแบบ (ตามที่ผู้ใช้ตกลง = ก. หน้ารายงาน ทุกหมวด รายงานต่อฐาน)

### 1. หน้ารายงาน (`templates/report.html`)

แสดงส่วนเลือกเมื่อ `META.perspective === 'sync'` และ URL ของหน้าเป็น `http(s)://…/runs/<id>/<ชื่อ>.html`
นอกนั้นไม่แสดงอะไรเพิ่ม (ไฟล์ที่เปิดออฟไลน์ ดูเหมือนเดิมทุกอย่าง)

- ทุกแถวมีช่องติ๊ก (`input type=checkbox` มี `aria-label` เป็นชื่อ object) ทั้งในการ์ดตารางและส่วน "โค้ดและของอื่น"
- หัวการ์ดแต่ละตารางมีช่อง "เลือกทั้งตาราง" ติ๊ก/ถอนเฉพาะแถวที่การ์ดนั้นแสดงอยู่ตามตัวกรองปัจจุบัน
- แถบเครื่องมือด้านบนเพิ่ม "เลือกที่แสดงอยู่ทั้งหมด" และ "ล้าง" (กรองชนิด SP ก่อนแล้วกดเลือกทั้งหมดได้)
- ที่เลือกไว้คงอยู่เมื่อเปลี่ยนตัวกรองหรือคำค้น เก็บในหน่วยความจำของหน้า (`Set` ของ id แถว)
- แถบลอยด้านล่าง (สไตล์กระจกเดียวกับแถบเครื่องมือ) แสดง "เลือกแล้ว K รายการ" ปุ่มล้าง และปุ่ม Sync script / Rollback script
  ปุ่มใช้ไม่ได้เมื่อเลือก 0 รายการหรือกำลังรอผล
- กดปุ่ม: `POST /api/runs/<id>/script` ด้วย `{ report, kind, rows }` (ใส่ header ตามข้อจำกัด)
  - สำเร็จและไม่มีคำเตือน: ดาวน์โหลดไฟล์ด้วย Blob ตามชื่อที่เซิร์ฟเวอร์ให้ แล้วแสดงบรรทัด "ได้ไฟล์ … (เลือก K จาก N รายการ)"
  - มีคำเตือน (`needs`): ยังไม่ดาวน์โหลด แสดงรายการ "<object> ต้องมี <ตาราง> ด้วย" พร้อมปุ่ม "เลือกให้ด้วย"
    (ติ๊กแถวที่ขาดแล้วสร้างใหม่) และ "ดาวน์โหลดเลย"
  - ผิดพลาด: แสดงข้อความของเซิร์ฟเวอร์ใต้คำอธิบายภาษาไทยหนึ่งบรรทัด
- ส่วนที่เพิ่มทั้งหมดซ่อนตอนพิมพ์ (บล็อก `@media print` เดิม) และใช้ตัวแปรสี/กระจกที่มีอยู่ ไม่เพิ่มสีใหม่

ภาพร่าง:

```
 [✓] ~ ต้องแก้   dbo.pile_pco  stored procedure
                 โค้ดข้างในต่างกัน sync จะแทนด้วยโค้ดของต้นแบบ
 [ ] ~ ต้องแก้   dbo.constant  stored procedure
 ╭──────────────────────────────────────────────────────╮
 │ เลือกแล้ว 1 รายการ   [ล้าง]  [Sync script]  [Rollback] │
 ╰──────────────────────────────────────────────────────╯
```

### 2. เซิร์ฟเวอร์ (`app/server.js`, `app/lib/runs.js`)

เส้นใหม่: `POST /api/runs/:id/script` เรียก `runs.selectedScript(id, { report, kind, rows })`

- ตรวจ: id ตรง `RUN_ID` และรันมีอยู่; `report` เป็นชื่อไฟล์ `.html` ล้วน (ไม่มี `/` หรือ `\`) ที่อยู่ในโฟลเดอร์รัน;
  `kind` เป็น `sync` หรือ `rollback`; `rows` เป็น array ไม่ว่างของจำนวนเต็มไม่ซ้ำ อยู่ในช่วง `0 … จำนวน diffs - 1`
  (400 เมื่อผิด, 404 เมื่อไม่มีรัน, 409 เมื่อไม่มี `.json` หรือ snapshot ของรันนั้น พร้อมข้อความว่าให้เทียบใหม่)
- หา `<base>` จากชื่อ `report` (รันเดี่ยวคือ `report`, batch คือชื่อไฟล์ของฐาน) แล้วเรียก engine ผ่าน
  `runPowerShell` ด้วยรูปแบบ `-Name:value` เหมือน `buildArgs`
- หมายเลขแถวห้ามส่งทางบรรทัดคำสั่ง (เพดานของ Windows ราว 32,000 ตัวอักษร ติ๊กหลายพันแถวจะล้ม): เซิร์ฟเวอร์เรียงจากน้อยไปมาก
  ตัดตัวซ้ำ เขียนเป็น JSON `{ "rows": [...] }` ลงไฟล์ชั่วคราวชื่อไม่ซ้ำใต้ `config.TMP` ส่งแค่ path ให้ engine และลบไฟล์นั้น
  กับไฟล์ผลลัพธ์ทิ้งหลังอ่านเสร็จ (รวมกรณี engine ล้ม)
- ตอบ `{ name: "<base>.selected.<kind>.sql", text, selected, total, needs }` เก็บ BOM ที่ engine เขียนไว้
  เส้นเดิมทั้งหมด (รวม `combined/…sql`) ไม่เปลี่ยน

### 3. engine (`Compare-Database.ps1`, ไฟล์ใหม่ `lib/SelectedScript.ps1`)

พารามิเตอร์ใหม่ (โหมดแบบ `-ListDatabases`: ทำงานแล้วออก พิมพ์ JSON ผลทาง stdout แต่ต้องไม่ต้องมี profile/server
และต้องไม่เปิดการเชื่อมต่อฐานข้อมูลเลย จึงต้องแยกก่อนโค้ดที่อ่าน profile ในบล็อกหลัก):
`-ScriptFromResult <path ของ <base>.json>`, `-ScriptSelection <path ของไฟล์ JSON ที่มี rows>`, `-ScriptKind sync|rollback`, `-ScriptOutput <path>`
stdout: `{ selected, total, needs: [ { row, object, needsRow, needs } ] }` ข้อผิดพลาด: exit 2 พร้อมข้อความ (รูปแบบเดียวกับโหมดอื่น)
engine ตรวจ `rows` เองอีกชั้น (ว่าง, เกินช่วง, ซ้ำ) ไม่เชื่อว่าเซิร์ฟเวอร์ตรวจมาแล้ว

`Write-SelectedScript` ทำสิ่งเดียว: อ่าน `diffs` จาก `.json` และ snapshot สองไฟล์ในโฟลเดอร์เดียวกัน (`Import-SchemaSnapshot`)
กรอง `diffs` ตามแถวที่เลือก แล้วเรียก `Write-SyncScript` หรือ `Write-RollbackScript` เดิมด้วยอาร์กิวเมนต์ชุดเดียวกับที่
`Invoke-DatabaseComparison` ใช้: label จาก `source.label`/`target.label`, `warnings` จาก JSON,
`TargetIncomplete` = ไม่ใช่ `target.canViewDefinition`, ชื่อฐานเป้าหมายจาก snapshot ฝั่ง target
ตัวแปรระดับสคริปต์ที่ตัวสร้าง script อ่าน (อย่างน้อย `$SelectedCategories`, `$Perspective`, `$IgnoreWhitespace`, `$IgnoreCase`,
`$IgnoreCollation`, `$CompareColumnOrder`) ต้องตั้งจาก `categories`/`perspective`/`options` ใน `.json` ให้ได้ผลเหมือนตอนเปรียบเทียบ
(ผู้สร้างต้อง grep หาตัวแปรที่อ่านจริงให้ครบ เป้าหมายข้อ 2 เป็นตัวพิสูจน์)

### 4. ตัวที่พึ่งตัวอื่น (`Get-SelectionNeeds`)

กฎที่ตรวจได้จาก snapshot: แถวที่เลือกเป็น FK หรือ trigger ซึ่งอ้างตาราง (FK: ตารางที่ชี้ไป, trigger: ตารางของมัน) ที่การเปรียบเทียบรายงานว่า
`OnlyInSource` (ตารางใหม่) แต่แถวตารางนั้นไม่ได้ถูกเลือก ให้ใส่ใน `needs` กฎอื่น (view/proc ที่อ้าง object ใหม่)
ตรวจไม่ได้ ไม่ต้องทำ แต่ README ต้องบอกตรง ๆ ว่าเช็คเฉพาะกรณีนี้ ที่เหลือให้ตรวจก่อนรัน

### 5. หัวไฟล์

ถ้าเลือกไม่ครบ ใส่ comment ในหัวไฟล์ว่าไฟล์นี้สร้างจากชุดที่เลือก K จาก N รายการ และถ้ามี `needs` ให้ระบุไว้ด้วยทุกครั้ง
(ไฟล์ที่ผู้ใช้ดาวน์โหลดทั้งที่ขาดตัวที่พึ่ง ต้องบอกเรื่องนี้ในตัวมันเอง ไม่พึ่งว่าหน้าเว็บเตือนไปแล้ว)
ถ้าเลือกครบ ห้ามมี comment เพิ่ม (เป้าหมายข้อ 2) ห้ามแก้ข้อความท้ายไฟล์ที่ `SCRIPT_TRAILER` ใน `runs.js` จับอยู่
วิธีใส่ (เช่น พารามิเตอร์ `-Note` ที่เป็นค่าว่างโดยปริยายบน `Write-SyncScript`/`Write-RollbackScript`) ให้ผู้สร้างเลือก

## การทดสอบ

ทุกข้อที่ไม่ต้องใช้ SQL Server รันได้ในเครื่องนี้ (LocalDB ใช้ไม่ได้: เทสต์ 19 ข้อข้ามอยู่แล้ว)

1. **engine (ไฟล์ใหม่ `test/engine-selected.test.ts`)** จาก `test/golden/<เคส>/` (`result.json`, สอง snapshot, `sync.sql`, `rollback.sql`):
   - เลือกทุกแถว ⇒ ได้ข้อความเท่ากับ golden หลังแทนค่าที่เปลี่ยนทุกครั้งด้วยวิธีเดียวกับ golden ทุกเคส ทั้ง sync และ rollback
     (ตรวจข้อนี้ก่อนอย่างอื่น ถ้า placeholder ใน golden ทำให้เทียบตรง ๆ ไม่ได้ ให้บอกผู้ใช้ก่อนเปลี่ยนวิธี)
   - เลือกแถวเดียว ⇒ มีคำสั่งของ object นั้น ไม่มีของแถวอื่น และมี comment "1 จาก N"
   - แถวว่าง / เกินช่วง / ซ้ำ ⇒ exit 2 พร้อมข้อความ
   - `needs`: FK หรือ trigger ของตารางใหม่ที่ไม่ได้เลือก ⇒ ถูกรายงาน เลือกตารางด้วย ⇒ ว่าง (เคสไหนมีให้ใช้ ถ้าไม่มี สร้าง snapshot จิ๋วเอง)
2. **เซิร์ฟเวอร์ (`test/app.test.ts`)** โฟลเดอร์รันจำลองจากไฟล์ golden: 400 / 404 / 409 ตามข้อ 2 ของการออกแบบ,
   header ขาด ⇒ 403, กรณีสำเร็จได้ `name`/`text`/`selected`/`total`
3. **รายงาน (`test/report.test.ts`)** ตรรกะล้วน ๆ ใน `createReportCore` (toggle, เลือกทั้งการ์ด, เลือกที่แสดงอยู่, ล้าง,
   ตัดสินว่าอยู่ในแอปจาก URL, สร้าง body ของ request, ข้อความ `needs`) รันใน vm เหมือนตรรกะเดิม
   และเทสต์เดิมต้องผ่านต่อ: ไม่โหลดอะไรจากข้างนอก, ตัวอักษรขั้นต่ำ 14px

## เรื่องที่ spec ไม่ได้พูดแต่ต้องไม่พัง (Review Focus)

1. เลือกเฉพาะแถว `OnlyInTarget` (script จริงมีแต่ comment ของ DROP) ต้องได้ไฟล์ถูกต้องที่บอกว่าไม่มีคำสั่งรัน ไม่ใช่ไฟล์ว่างหรือ error
2. รายงานเก่าที่รันถูกลบไปแล้ว หรือเปิดคนละรัน: ตอบ 404/409 พร้อมข้อความ ไม่ล้มเงียบ ๆ และแถวที่ส่งมาเกินจำนวนจริงต้องไม่ทำให้ engine พัง
3. ติ๊กหลายพันแถว (batch ใหญ่): body ต้องไม่ชนเพดาน 1 MB ของ `readBody`, แถวไม่ไปทางบรรทัดคำสั่ง (เพดาน Windows ราว 32,000 ตัวอักษร)
   และต้องไม่ช้าจนดูเหมือนค้าง (ปุ่มแสดงสถานะรอ) ควรมีเทสต์ที่ส่งแถวหลักหมื่นผ่านเซิร์ฟเวอร์
4. กดปุ่มซ้ำระหว่างรอ: ต้องไม่สร้างไฟล์สองครั้งหรือสองกระบวนการ
5. ชื่อฐานที่มีอักขระพิเศษหรือไทยในชื่อไฟล์ดาวน์โหลด: ชื่อต้องใช้ได้บน Windows

## ปล่อยให้ผู้สร้างตัดสินใจ

## ที่ต่างจากแผนตอนสร้างจริง

ผู้ใช้สั่งให้ลงมือหลังเห็นแผน พร้อมเพิ่มความต้องการ 2 ข้อจากหน้ารันของจริง (`#/runs/<id>`): เพิ่มปุ่ม "sync script แบบเลือกเอง"
ข้างปุ่ม sync script เดิมของแต่ละฐาน และเปลี่ยนลิงก์ในแถวฐานเป็นปุ่ม จึงเพิ่มและปรับดังนี้

- **หน้ารัน (`app/public/app.js`):** แถวของฐานมีปุ่ม รายงาน / sync script ทั้งฐาน / **sync script เลือกเอง** (สีหลัก) / rollback script ทั้งฐาน
  ปุ่มเลือกเองเปิดรายงานที่ `#select` มีเฉพาะฐานที่มีแถวให้เลือก รันฐานเดียวมีปุ่ม "Sync script เลือกเอง" ในแถวปุ่มด้านบน
- **โหมดเลือกในรายงาน:** ช่องติ๊กไม่แสดงตลอด แสดงเมื่ออยู่ในโหมดเลือก (เข้าด้วย `#select` หรือปุ่ม "เลือกรายการเพื่อสร้าง script" บนแถบเครื่องมือ)
  เพื่อให้หน้าอ่านปกติสะอาดเหมือนเดิม
- **รายงานของรันเก่า:** รายงานที่สร้างก่อนฟีเจอร์นี้ฝังเทมเพลตเก่าไว้ในไฟล์ จึงไม่มีช่องติ๊ก แอปเลยเปิดรายงานผ่านเทมเพลตปัจจุบันด้วยค่าเดิมของไฟล์
  (`app/lib/report-page.js`) ไฟล์ในโฟลเดอร์ไม่ถูกแก้ และ `?download=1` ได้ไฟล์เดิม ผลข้างเคียงที่ตั้งใจ: รายงานเก่าได้หน้าตาปัจจุบันด้วย
- **แถวส่งผ่านไฟล์:** `-ScriptSelection` เป็นไฟล์ JSON ตามแผน ไม่ใช่พารามิเตอร์ตรง ๆ เซิร์ฟเวอร์เขียนไฟล์ชั่วคราวใต้ `data\tmp` แล้วลบทุกครั้ง
- **ไม่มี `acknowledgedNeeds`:** ไฟล์ sync ใส่ `WARNING:` ที่หัวไฟล์ทุกครั้งที่มีตัวที่พึ่งอยู่ในชุดที่เลือก ไม่ต้องให้หน้าส่งฟลากเพิ่ม
  (rollback ไม่มี `WARNING:` เพราะย้อนเฉพาะสิ่งที่ sync ของชุดเดียวกันทำ)
- **ชื่อพารามิเตอร์หัวไฟล์:** `-HeaderNotes` ไม่ใช่ `-Note` เพราะ PowerShell ไม่สนตัวพิมพ์เล็กใหญ่ `$Note` ชนกับ scriptblock `$note` ที่ `Write-SyncScript` ใช้อยู่
- **`$IgnoredProps`:** engine คำนวณจากสวิตช์ตอนเริ่มทำงาน โหมดนี้จึงต้องสร้างใหม่จาก `options` ในผลเปรียบเทียบ (ไม่งั้น `-CompareColumnOrder` หาย)
  เทสต์ "ติ๊กทุกแถว = ไฟล์เดิม" ของเคส `edge-loose` จับข้อนี้ได้

### เพิ่มหลังลงมือ: ดู script ในแท็บใหม่ (ผู้ใช้ขอ)

แถบล่างของรายงานมีปุ่ม "ดู" คู่กับ "ดาวน์โหลด" ของ sync และ rollback ปุ่ม "ดู" เปิดแท็บใหม่ที่แสดง script ทันที พร้อมปุ่ม "คัดลอก" และ "ดาวน์โหลด"
สำหรับคนที่ไม่อยากดาวน์โหลดไฟล์ อ่านแล้วคัดลอกไปวางเอง

- แท็บถูกเปิดตอนกดปุ่ม (`window.open('', '_blank')` ก่อนรอ) เพราะตัวบล็อก popup ไม่ให้เปิดหลังรอผลนาน แล้วเขียนหน้า (`viewerPage` ใน `createReportCore`) ลงไปเมื่อได้ script
- หน้านั้นเก็บข้อความ script ไว้ในตัว (JSON ใน `<script>` ที่เขียน `<` เป็น `\u003c` และตัวคั่นบรรทัดเป็น escape) จึงใช้ได้เมื่อปิดรายงานแล้ว
  ข้อความที่แสดงและคัดลอกไม่มี BOM (ไม่งั้นวางใน SSMS แล้วมีอักขระที่มองไม่เห็น) ส่วนปุ่มดาวน์โหลดในแท็บใช้ข้อความที่มี BOM ตามไฟล์
- ถ้ามีตัวที่พึ่งตัวอื่น (`needs`) แท็บที่เปิดไว้บอกว่ารอการตัดสินใจในหน้ารายงาน ("เลือกให้ด้วย" ปิดแท็บนั้น, "เปิดดูเลย" เขียน script ลงแท็บเดิม หรือแท็บใหม่ถ้าถูกปิดไปแล้ว)
- บทเรียนตอนสร้าง: ซอร์สของหน้ารายงานห้ามมีคำว่า `</script>` ตัวจริงแม้ใน comment และเครื่องมือแก้ไฟล์แปลง `\u2028` ใน regex เป็นตัวคั่นบรรทัดจริงจนสคริปต์พัง ต้องเขียนด้วยสคริปต์ที่ไม่แปลง
